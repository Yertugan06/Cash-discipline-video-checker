### `validation/`

- `validation/validation-evidence/harness/score.py`, `score_utils.py`: the
  scorer that `eval/run_eval.py` runs. Current. `gt.py` and `split.py` there
  are retired stubs: the ground truth is built by `python -m eval.ground_truth`.
- `validation/validation-private/gt.json`, `split.json`: what the scorer
  compares against. `gt.json` is generated by `eval.ground_truth --write`; do
  not edit it by hand. `split.json` is frozen: nothing writes it, and
  `eval.ground_truth` fails if it no longer follows from `gt.json`.
- The other harness scripts (`f1_rules.py`, `f3_discovery.py`,
  `f4_cascade.py`, `f2_probe.py`, `verify_windows.py`, ...) and `logs/` are the
  experiments behind A00 and A04-A09. Kept here, not in `archive/`, because
  they share the scorer's paths.

### Labels: where the ground truth comes from

- All label sources live in the team data root (`datathon:~/data`, synced and
  hash-checked by `python -m eval.sync_data`, see `eval/README.md`).
- Organizer labels: `open/open_labels.xlsx`. Verdict and one or more seconds
  per video. The only ground truth for verdict and timing.
- Team annotation: `team/Таблица_нарушений.xlsx`. Violation type and norm per
  event, used for the scorer's rule (norm-code) check; and violation/clean
  clip pairs, which `split.py` uses to keep a pair on the same side of the
  dev/lockbox split. Reviewer decisions about it: `team/reviews.json`.
- `eval/ground_truth.py` reads them and writes
  `validation/validation-private/gt.json` and `discrepancies.json`.
- The service itself never reads labels (`tests/test_no_label_access.py`).

## Paths moved on 2026-10-17

Logs written before the move (`*.log`, `*.txt`, `*.csv`, `*.json` in
`attempts/` and `validation/validation-evidence/logs/`) still show the old
paths. Map them with this table:

| Old path | New path |
|---|---|
| `reasearch1/validation-evidence/` | `validation/validation-evidence/` |
| `reasearch1/validation-private/` | `validation/validation-private/` |
| `reasearch1/*.md` | `archive/research1/*.md` |
| `reasearch2/` | `archive/vm-copies/` |
| `agents/`, `skills/` | `archive/agents/`, `archive/skills/` |
| `data/prepared/{README.md,events.jsonl,schema.json,validation_report.json}` | `archive/data-prepared-old/` |

The research harness takes its root as an argument: what used to be
`python -I .../gt.py reasearch1` is now `python -I .../gt.py validation`, and
`eval/run_eval.py --root` defaults to `validation`.
