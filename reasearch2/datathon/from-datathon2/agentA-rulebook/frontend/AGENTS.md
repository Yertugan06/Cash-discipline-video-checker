
# React Frontend Guidelines

- Use React functional components and TypeScript strict mode.
- Prefer small, cohesive components with clear responsibilities.
- Organize code by feature when features become substantial.
- Keep API calls in a dedicated typed client layer.
- Use shared request/response types from the agreed API contract.
- Do not duplicate backend business rules as an independent authority.
- Keep state minimal; derive values instead of storing duplicates.
- Avoid unnecessary global state and effects.
- Handle loading, empty, error, and success states explicitly.
- Prefer semantic HTML and accessible controls.
- Keep responsive layouts usable on desktop and mobile.
- Reuse existing components and design tokens.
- Avoid new UI libraries without a clear reason.
- Run TypeScript checks, linting, and relevant component tests.
