# Предложение по архитектуре: «состояние сцены + правила из кодекса + локальная VLM»

*Для команды ForteBank Datathon 26, 17.10.2026. Основано на разборе 42 роликов из обучающего датасета (`dataset_analysis.md`, `Таблица_нарушений_v2.xlsx`) и на кодексе норм (`codex/`).*

## Зачем менять схему «поза → VLM → RAG»
Скорее всего, большинство команд сделают так: «фильтр по движению → VLM на подозрительных кусках → RAG по нормам». У этой схемы три слабых места. Все три видны прямо на нашем датасете.

1. **Нарушения в основном — это состояние, а не движение.** В парах нарушение/норма движения почти одинаковые, а различаются детали:
   - X-28/X-29 — экран заблокирован или нет;
   - X-22/X-23 — ключ в замке сейфа;
   - X-20/X-21 — сейф открыт;
   - X-32/X-31 — дверь не закрыта.

   Фильтр по позе или «активности» такое пропустит. А пропуск нарушения по ТЗ недопустим.
2. **Таймкод.** За точный таймкод и кадр дают 15 баллов, а VLM плохо называет точную секунду. Метки в разметке стоят на **событиях**: кассир ушёл, вошёл второй человек, деньги взяты без документа.
3. **Нормы.** Генерация ссылок по RAG рискованна: за выдуманный или неточный пункт снимают баллы по критерию 4. Нормативная база конечная — её можно один раз полностью разложить в таблицу (кодекс) и подставлять нормы по ID.

## Схема

```
видео (.mov, любой кодек/ракурс)
 └─ 0. ffmpeg: нормализация, 2–4 кадра/с, pts → таймкоды
 └─ 1. Разметка сцены (1 раз на видео): стол, сейф, дверь, ноутбук, счётчик, детектор → зоны
 └─ 2. Дешёвое восприятие по кадрам: люди + трекинг → роли (кассир / клиент / инкассатор / посторонний)
 │     предметы на столе: деньги, сумка, телефон, еда и стакан, пальто и сумка, документы
 │     состояния: сейф открыт, дверь открыта, экран разблокирован, ключ в замке
 └─ 3. Журнал событий с точным временем:
 │     вход/выход, кассир покинул зону, новый клиент, передача денег/сумки, сейф открыт/закрыт…
 └─ 4. Движок правил: каждая строка кодекса → шаблон по событиям и состояниям → кандидат + таймкод
 └─ 5. Локальная VLM — только на окнах кандидатов:
 │     а) проверка: вопросы да/нет по кропам до и после события → отсеивает ложные срабатывания
 │     б) «открытый мир»: краткое описание окон событий → выбор ID из кодекса (закрытый список) → новые типы
 │     в) человеческое описание по фактам
 └─ 6. JSON собирает сервис: вердикт, таймкод из события, 1–3 кадра,
       описание, норма из кодекса (цитата + ссылка + «прямая/косвенная»)
```

### Шаг 1. Разметка сцены: ракурс в финале другой
Координаты зон не задаём вручную. По первым кадрам (или по медианному фону) детектор с открытым словарём ищет «стол», «металлический шкаф/сейф», «дверь», «ноутбук», «счётную машину». Из найденного строятся зоны: «рабочее место кассира», «сторона клиента», «вход».

У нас в датасете уже 6 разных положений камеры. Используйте их для проверки, что разметка сцены находит зоны правильно.

### Шаг 2. Состояния вместо позы
| Состояние | Как дёшево определить | Когда звать VLM |
|---|---|---|
| Сейф открыт | разница кропа сейфа с эталоном «закрыт», взятым в начале видео | при сомнении |
| Дверь открыта | разница кропа двери с эталоном | при сомнении |
| Экран разблокирован | яркость и текстура кропа ноутбука (таблица ≠ экран блокировки ≠ закрытая крышка) | при сомнении |
| Ключ в замке | слишком мелко для дешёвой модели | всегда, на кропе в высоком разрешении |
| Деньги / сумка / документы на столе | детектор с открытым словарём + разница стола «до/после» | для подтверждения |
| Кассир на месте | трекинг человека в зоне рабочего места | — |

Позу оставить только как вспомогательный сигнал: «рука у рта» (еда), «рука к карману».

### Шаг 4. Правила из кодекса (примеры)
| Правило | Шаблон | Норма | Ролики |
|---|---|---|---|
| Уход с рабочего места | `cashier_leaves_workplace` (>3 с) **и** (`cash_on_desk` ∨ `bag_on_desk` ∨ `safe_open` ∨ `key_in_lock` ∨ `laptop_unlocked` ∨ `documents_on_desk`) → таймкод = момент ухода | 231 п. 20 ч. 2, п. 22, п. 80; 53 п. 71 | X-11, 15, 22, 24, 26, 28 |
| Грязный стол при новом клиенте | `client_arrives`, а деньги прошлой сессии ещё на столе | 231 п. 20 ч. 2 | X-4, X-38 |
| Дверь не закрыта | кассир вошёл, `door_open` дольше N с | 14 п. 8, п. 16 пп. 1) | X-32, X-33 |
| Посторонний | человек в зоне кассира — не кассир | 14 п. 8, п. 16 пп. 1) | X-30, X-33 |
| Клиент ушёл до пересчёта | `client_leaves`, пока деньги сессии в обработке | 231 п. 20 ч. 1 | X-34 |
| Без удостоверения | в сессии `cash_client_to_cashier` раньше любого `id_document_shown` | 231 п. 19 пп. 1), п. 7 | X-2 |
| Инкассатор | `bag_handover`, затем `collector_leaves` быстрее N с без `seal_inspected` | 231 п. 24, п. 101 + Прил. 4 | X-17 |
| Сейф открыт | `safe_open`, а кассир дальше от сейфа, чем ~1 м, дольше N с | 231 п. 20 ч. 2 | X-20 |
| Личные вещи и еда | на столе есть `personal_items` / `food_drink` | 231 п. 12 | X-40, X-46 |

Пороги N подбирать на 42 размеченных роликах. Цель — ноль пропусков при минимуме ложных срабатываний.

### Шаг 5. Новые типы нарушений в финале
1. **Кодекс** покрывает все визуально проверяемые нормы, а не только 22 нарушения из датасета. Под строки кодекса без примеров в датасете заранее пишем правила.
2. **Открытый мир:** VLM коротко описывает каждое окно события, а затем выбирает **ID из кодекса** из закрытого списка или отвечает «нет». Так модель никогда не сочиняет норму.
3. **Свои съёмки** (FAQ разрешает это прямо). 10–20 коротких роликов на телефон: другие ракурсы и нарушения из кодекса, которых нет в датасете. Например:
   - телефон с камерой в кассе;
   - пересчёт под столом или вне кадра;
   - передача денег коллеге без документа;
   - кассир уходит во время обслуживания;
   - упаковка денег без контролёра.

   Это лучший способ проверить «новый угол» и «новые типы» до финала.

## Почему это сильнее типичного решения
| Критерий (баллы) | Типичная схема | Эта схема |
|---|---|---|
| Обнаружение (25) | фильтр по позе пропускает нарушения-состояния | события + состояния на каждом уходе и приходе |
| Таймкод (15) | VLM угадывает секунду | время события из трекера (pts) |
| Тип (15) | свободный текст VLM | ID из кодекса |
| Нормы (15) | RAG может переврать пункт | дословная цитата и якорь на adilet, пометка «косвенная» |
| Новый ракурс (10) | зависит от промпта | зоны находятся детектором в каждом видео |
| Продукт / техника (20) | — | журнал событий и правила легко показать жюри; быстро |

## Модели: только open source с коммерческой лицензией
YOLO / Ultralytics нельзя (AGPL). Кандидаты — **лицензию каждой модели проверить по карточке перед использованием**:
- **детекция с открытым словарём:** Grounding DINO (Apache-2.0), OWLv2 (Apache-2.0), Florence-2 (MIT);
- **детекция людей:** RT-DETR (Apache-2.0), RTMDet / MMDetection (Apache-2.0);
- **трекинг:** ByteTrack (MIT);
- **поза (опционально):** RTMPose (Apache-2.0);
- **VLM:** Qwen2.5-VL-7B-Instruct (Apache-2.0) или более новые аналоги. У некоторых семейств маленькие версии выходят под исследовательской лицензией;
- **сервинг:** vLLM (Apache-2.0) с ограничением формата ответа JSON-схемой.

## NVIDIA Brev
- **Можно:** арендовать GPU-машину и запускать на ней свои open-weight модели (vLLM / transformers). Модель работает внутри вашего сервиса — это «локально» в смысле ТЗ.
- **Нельзя:** вызывать размещённые NVIDIA API (NIM endpoints на build.nvidia.com и т. п.). Это облачный AI-API, за него по п. 35 FAQ дисквалификация. Готовые NIM-контейнеры лучше тоже не брать: у них отдельная лицензия NVIDIA; используйте vLLM.
- **Деньги:** оплата почасовая, а остановленная машина при перезапуске может не получить GPU. Оставьте резерв бюджета, чтобы машина гарантированно работала, пока жюри проверяет решение. Можно также хостить финал на своём железе через туннель.
- **Данные:** по FAQ — только в рамках хакатона. После хакатона удалите датасет с арендованной машины.

## Порядок работ
1. Оценочный скрипт: 42 ролика, дубликаты X-4/X-47 и X-5/X-48 держать вместе. Метрики: вердикт, ошибка таймкода, тип.
2. Нормализация видео, люди + трекинг, журнал событий. Сразу закрывает уход с места, входы и посторонних.
3. Состояния сейфа, двери, экрана и стола через кропы и сравнение с эталоном.
4. Движок правил из кодекса + проверка кандидатов VLM.
5. Описание окон событий → выбор ID кодекса.
6. Свои съёмки → прогон → подбор порогов.
