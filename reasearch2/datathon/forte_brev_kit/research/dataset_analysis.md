# ForteBank Datathon 26: разбор материалов

Дата разбора: 17.10.2026. Что лежит рядом:
- `video_annotations.csv` — покадровое описание всех 42 роликов;
- `contact_sheets/` — по одному листу на видео: обзор плюс окно ±4–5 с вокруг метки (красная рамка на кадре метки);
- `normative_sources.md` — нормативная база РК.

## 1. Суть кейса
- Нужен **локальный** AI-сервис: веб-интерфейс плюс API `POST /api/v1/analyze` и `GET /api/v1/jobs/{id}`, ключ в заголовке `X-API-Key`. Облачные модели запрещены, за это дисквалификация. Звук и распознавание лиц тоже запрещены.
- Вердикт `violation` / `no_violation`. Для каждого нарушения сервис возвращает `type`, `timecode_sec`, `description` и 1–3 JPEG-кадра в base64. Лимит — 5 минут на видео.
- Оценка (100 баллов):
  - вердикт — 25;
  - таймкод и кадр — 15;
  - тип — 15;
  - ссылки на нормы — 15;
  - устойчивость к новому ракурсу — 10;
  - продукт — 10;
  - архитектура — 10.
- Позиция организаторов по ошибкам: пропуск нарушения недопустим, ложных срабатываний должно быть как можно меньше.
- Важно из FAQ:
  - закрытого списка типов нет, в тесте будут новые типы;
  - финальное видео снято под другим углом;
  - тест — 5+ видео;
  - модели только open source с лицензией, разрешающей коммерческое использование. Ultralytics YOLO (AGPL-3.0) под вопросом, надёжнее брать модели с Apache-2.0 или MIT.

**Вывод для приёма файлов.** Формат теста может отличаться от обучающего, поэтому на входе всё нормализуем через ffmpeg:
- декодировать любой кодек, автоповорот оставить включённым;
- привести к единой высоте (например, 848) и к фиксированному fps по **pts** (`fps=N`), а не по номеру кадра — именно так получаются правильные таймкоды;
- аудио игнорировать.

Таймкод в ответе считать от pts первого кадра.

Чего в открытых актах **нет**, и это надо честно писать в описании:
- прямого запрета посторонних в кассе БВУ;
- нормы «пересчёт в зоне камеры» для БВУ;
- нормы «блокировать ПК при уходе» (есть только автоблокировка по таймауту);
- нормы «один клиент одновременно».

Важное исключение против ложных срабатываний: № 231, **п. 32** — целые корешки в неповреждённой упаковке выдаются без полистного пересчёта.

## 5. Выводы для решения
1. **Вердикт важнее всего** (25 баллов), и пропуск недопустим. Порог настраивать на полноту, а ложные срабатывания гасить проверкой «есть ли контрастный признак».
2. **Нарушения — это в основном «состояние в момент события»**, а не отдельное действие. Классификатор клипов даст мало. Практичная схема:
   - детекция людей, рук и объектов (open-vocabulary, Apache/MIT);
   - трекинг ролей по зонам (кассир за столом, клиент напротив, вход в дверь);
   - правила по событиям («кассир вышел из зоны → что осталось на столе / сейф / экран / ключ»);
   - локальная VLM (например, Qwen2.5-VL, Apache-2.0) для описания и проверки спорных кадров.
3. **Таймкод.**
   - Нарушение «действием» — момент самого действия: вход постороннего, взятие денег.
   - Нарушение «бездействием» — момент, когда бездействие стало необратимым: кассир отошёл от стола и не закрыл, не убрал, не заблокировал.
   - Именно так поставлены метки в разметке.
4. **Ракурс.** Нельзя хардкодить области кадра: сейф, дверь и стол в шести сетапах стоят в разных местах, а тест снят под новым углом. Зоны нужно находить детектором в каждом видео.
5. **Несколько событий на видео** — норма (X-4: 57 с и 68 с). API это допускает: `violations` — список.
6. **Перед обучением дедуплицировать** X-4/X-47 и X-5/X-48.
