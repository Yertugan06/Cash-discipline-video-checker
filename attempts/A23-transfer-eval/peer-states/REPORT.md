The useful transfer is frozen crop features plus a very small learned head and correct group separation. An extra larger LLM does not repair noisy crop labels or inadequate geometry. A DINO download, peer pickle loader, peer pipeline, legal rules and tile-label bootstrap are unnecessary for the first prototype.

`crop_probe.py` is own code using **our installed LAION CLIP image encoder** (locked in main's `models.lock.json`, revision `1a25a446712ba5ee05982a381eed697ef9b435cf`) and NumPy. Worker-1 has NumPy 2.5.2, TF 4.57.3, torch 2.10.0+cu128; sklearn is absent and was not installed. It uses the same no-center-crop 224-pixel processor call as `LocalModels.state`, and reuses our `crop_image`, `extract_jpeg`, `probe`, `Scene` and config. Only the CLIP model loads; no detector stack or LLM is added. This is a feasibility probe, not an assertion that CLIP matches DINOv2 features.

The script selects one midpoint per human-confirmed stable interval, requires at least 0.5 s coverage and all three known classes in training, verifies video/cache hashes and recording cutoff, and uses only cached automatically calibrated laptop geometry. It refuses missing/invalid geometry and labels. Train/test share neither setup group nor source/parent SHA, including mirrors. Unknown synthetic labels cannot enter training; mirrors cannot become independent held-out clips. No adjacent-frame random split or invented thousands of labelled frames. Actual derived synthetic lineage still requires human/parent verification of the manifest; strings alone cannot prove it.

It exports finite coefficients/intercepts/class order as **head.json**, with source model/processor hashes and label-manifest provenance. `apply_head(feature, head)` receives only image features and JSON coefficients; names, timestamps, annotation references and verdicts never enter that runtime-shaped function. Computed scores are explicitly **uncalibrated**. The final diagnostic uses existing main thresholds, with no outcome-based tuning; low score/margin stays unknown. Do not convert this auxiliary classifier into authoritative visual-state evidence without measuring it on independent group labels and difficult/occluded crops.

Concrete blocker: `label-coverage.json` pins the 42-entry human export. The eight relevant manual summaries have **zero timed rows**. X22/X23/X29 establish that a lock action occurred, but neither its timing nor recognizable lock-screen pixels at any selected time. X11/X12's identical prose leaves the later screen state unresolved; Qwen agreement is not a human training label. No eligible timed laptop intervals/setup assignments are available. `human-intervals.json` therefore contains **zero samples**, not guessed negatives or model-bootstrapped answers. Requested human interval clarification while preparing code; no dependent training ran. Safe summaries likewise cannot supply arbitrary timed crop labels.

Measured result: six numeric fixture predictions survived JSON round-trip, ambiguous vector abstained, NaN/zero vectors were rejected, source-parent leakage was rejected; **0.062438 s**, no neural inference. This is arithmetic/setup evidence, not six real crop successes. The real empty manifest correctly exited 1 with `LABELS_REQUIRED` before torch/model imports (`validation-check.json`). Static inventory verified 11 joblib files and zero safe head exports. No broad tests or peer execution.

After human interval review, fill the explicit fields in `human-intervals.json`, keep all transforms with their original parent/setup, and run `cpu-command.json` for label/split validation. Then the parent can execute `gpu-command.json` outside the sandbox. It uses worker-1 Python, offline weights, a nonblocking global GPU flock, 180 s internal processing deadline and 210 s outer timeout. **LABELS_REQUIRED; not GPU_RUN_READY with current manifest.** Successful local execution writes numeric predictions/errors and source hashes, elapsed time, and JSON head. Failure raises an explicit error; never produces a compliant/default state. Decoded images stay in local memory and are never emitted.

Integration proposal only after a successful labelled probe: consume the existing normalized image feature inside `LocalModels.state` with this JSON head and attach its three scores/source/uncertainty as auxiliary context. This avoids a second feature model and preserves image-primary VLM questions. No production patch is justified yet: learned probability calibration, occlusion/cutoff behavior, setup transfer, real GPU latency and CV benefit remain unmeasured. All 40 public clips influenced development, so any forthcoming group split is a development diagnostic, not a new held-out accuracy claim.
