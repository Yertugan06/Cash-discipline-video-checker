# Usage

## 1. Submission details (jury)

| Item | Value |
| --- | --- |
| UI | https://forte-checker-wwi4jcrss.gobrev.dev/ |
| API | https://forte-checker-wwi4jcrss.gobrev.dev/api/v1 |
| API key | Generated by the team and handed to the jury out of band, with the submission package. Never committed; it lives only in `.env` on the host (mode 600) |
| Deployed | commit `277ac67` on the team's L4 host (`datathon`), `DETECTOR=f1`, `RULE_SCOPE=detector` (section 4) |

The API key is sent in the `X-API-Key` header. Requests without a valid key
get `401 Unauthorized`.

## 2. API

The two jury endpoints match task.md §10 exactly: the jury contract is never
renamed or extended with new required fields.

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/api/v1/analyze` | Upload a video in the `file` field: `.mov`, `.mp4` or `.mkv`, up to 64 MiB and 180 s. Returns `202` with `{"job_id": "..."}` |
| `GET` | `/api/v1/jobs/{job_id}` | Poll status/result: `processing`, `done` or `failed` |
| `GET` | `/api/v1/jobs/{job_id}/trace` | Optional extra, not part of the jury contract: the detector's debug trace for a job (calibration, events, rule findings, per-frame boxes). Same API key |

One job's processing budget is 270 s, inside the 5 minutes the jury contract allows before a video counts as
unprocessed (task.md §10, FAQ 14). The service runs one job at a time, so a
second upload waits in a queue (`docs/LIMITATIONS.md`, "Upload concurrency").

### Jury `curl` (form from task.md §10)

```bash
curl -X POST https://forte-checker-wwi4jcrss.gobrev.dev/api/v1/analyze \
     -H "X-API-Key: <key>" -F "file=@video_017.mov"
# -> {"job_id": "3f2a9c1e0b7d4e5f8a9b0c1d2e3f4a5b"}

curl https://forte-checker-wwi4jcrss.gobrev.dev/api/v1/jobs/3f2a9c1e0b7d4e5f8a9b0c1d2e3f4a5b \
     -H "X-API-Key: <key>"
```

The same in one command, with the result checked against the contract:

```bash
API_KEY=<key> python scripts/jury_client.py https://forte-checker-wwi4jcrss.gobrev.dev video_017.mov
```

### Responses

While the job runs:

```json
{ "job_id": "3f2a9c1e0b7d4e5f8a9b0c1d2e3f4a5b", "status": "processing" }
```

A `done` response looks like this (illustrative values; see
`backend/contracts.py:DoneJob` for the exact, frozen required shape). `type`,
`timecode_sec`, `description` and `evidence_frames` are the jury contract; the
rule lifecycle, detection confidence and structured citation metadata are
optional extras used by the UI:

```json
{
  "job_id": "3f2a9c1e0b7d4e5f8a9b0c1d2e3f4a5b",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Наличные/ценности оставлены без присмотра: кассир покинул рабочее место",
      "timecode_sec": 44.2,
      "description": "Что видно на видео. Признаки возможного нарушения: ...",
      "evidence_frames": [
        { "timestamp_sec": 44.2, "image_base64": "/9j/4AAQ..." }
      ],
      "rule_id": "L-NO-CASH-ON-LEAVE",
      "source": "Постановление НБРК №231, п.20, п.22",
      "source_url": "https://adilet.zan.kz/rus/docs/V1900019680",
      "source_quote": "...",
      "strength": "direct",
      "citation_status": "pending",
      "jurisdiction": "KZ",
      "document_title": "Об утверждении Правил осуществления кассовых операций ...",
      "issuing_authority": "Правление Национального Банка Республики Казахстан",
      "act_number": "231",
      "adopted_on": "2019-11-29",
      "business_status": "confirmed",
      "implementation_status": "implemented",
      "detection_confidence": 0.82
    }
  ],
  "warnings": [],
  "coverage": { "step_s": 0.5, "planned": 240, "done": 240, "failed": 0, "deadline_hit": false, "mode": "full" }
}
```

`verdict` is `"violation"` («Обнаружены признаки возможных нарушений») when
at least one finding survives, otherwise `"no_violation"` («Нарушение не
обнаружено») with an empty `violations` list. At most 3 findings are returned
per video. `type` is always one of the names in
[`VIOLATION_TYPES.md`](VIOLATION_TYPES.md), never free text.

A `failed` response always carries a human-readable `error` and is never
replaced by a fabricated `no_violation`:

```json
{ "job_id": "3f2a9c1e0b7d4e5f8a9b0c1d2e3f4a5b", "status": "failed", "error": "..." }
```

A video longer than 180 s or one ffprobe cannot read is accepted, then fails
this way.

### Errors

| Code | When |
| --- | --- |
| `401` | Missing or wrong `X-API-Key` |
| `404` | Unknown `job_id` (results are purged 24 h after the job ends) |
| `413` | Upload larger than 64 MiB |
| `415` | File extension other than `.mov`, `.mp4`, `.mkv` |
| `422` | Empty file, or no `file` field |

### Health

No API key needed; the body is only `{"status": ...}`.

- `GET /healthz` - liveness.
- `GET /readyz` - readiness: `200` once the model weights are present and
  match `models.lock.json` (`DETECTOR=f1`) or vLLM answers (`DETECTOR=vlm`),
  `503` otherwise.

## 3. UI usage

1. Open https://forte-checker-wwi4jcrss.gobrev.dev/.
2. Enter the API key in the "API key" field. It is kept only in the page's
   memory for the current session - never written to `localStorage`,
   `sessionStorage`, a cookie, or the URL, and never shipped in the frontend
   bundle. Reloading the page clears it; it must be re-entered.
3. Choose a `.mov`, `.mp4` or `.mkv` video and submit.
4. The page shows an explicit "processing" state and polls the job until it
   is `done` or `failed`.
5. On `done`, the page shows the verdict, then, for every violation: its
   type, timecode (mm:ss and seconds), description, 1-3 evidence frames and
   the norm block (source act + punkt, verbatim quote, a link to the source,
   and a citation badge: "verified" only for a human-verified norm, otherwise
   «ожидает проверки»).
6. If the video could not be fully covered within the processing deadline
   (`coverage.deadline_hit`) or the pipeline reported quality warnings (for
   example, zones not calibrated confidently), a visible warning banner
   explains this before the results.
7. A «Пример (демо-данные)» / "Sample (demo data)" button in the upload panel
   loads a synthetic `DoneJob` fixture (`frontend/src/fixtures/sampleDoneJob.ts`)
   so the result layout can be reviewed without uploading a real video.

## 4. Running it yourself

### Current A21 review service

The validated service is on datathon2: checker 8003 and gateway 8103 on the same VM.
Open `/evaluation` for verdict and observation audits, `/annotate` for whole-clip
comments or detailed timelines, and `/compare` for preserved runs. The previous 8102
preview is stopped. See [the canonical startup and tunnel instructions](../realtime/README.md#current-one-vm-review-service).

This is `DETECTOR=f1` with local `F1_VISUAL_CHECKS=1`, not the alternative
`DETECTOR=vlm` server. Only safe-state checks are enabled; the helper supplies no
cash/ID detections. It uses local model weights and an explicitly selected Python
worker environment. [Measured results and limits](../attempts/A21-deadline/RESULTS.md).


### With Docker Compose (production-like)

```bash
python3 scripts/download_weights.py          # once, needs internet; -> ./weights, checked against models.lock.json
cp deploy/.env.example .env && chmod 600 .env
# edit .env:
#   API_KEY      required, e.g. `openssl rand -hex 32`
#   DETECTOR     f1 (default, deployed); vlm is the alternative and needs deploy/vllm/ first
#   RULE_SCOPE   jury (default) reports only rules whose norms a person verified, and refuses
#                to start while there are none; detector reports every enabled rule with its
#                citation marked pending. No norm is verified yet, so use detector for now.
#   API_HOST     127.0.0.1 (default); 0.0.0.0 only behind a proxy that connects from outside
#                the host, such as Brev's (deploy/README.md, "Public URL")
docker compose -f compose.yaml -f compose.gpu.yaml up -d --build   # GPU
# or CPU only:  docker compose -f compose.yaml up -d --build
curl -sf http://127.0.0.1:8000/healthz
curl -sf http://127.0.0.1:8000/readyz
```

UI and API are served together on port 8000. After the weights are
downloaded, processing needs no internet access. See `backend/config.py`
(`Settings`) for every environment variable and its default, and
[`deploy/README.md`](../deploy/README.md) for publishing the service (Brev
port exposure, Caddy, systemd).

### Experimental desk object history (A18)

`desk_objects` in `config/perception.yaml` defaults to `false`. For an isolated
comparison through the F1 API, set it to `true` in that file or in the file
selected by `PERCEPTION_CONFIG`. This switches the leave rules to objects
tracked by desk changes and named from their history. It reuses the decoded
2 fps frames and the same job deadline. Per-job traces include
`desk_objects_enabled` and each desk object's observations, origin, counting
clue, detector kind and final identity. An unreadable frame or a frame count
mismatch fails the job explicitly.

A18 failed its accuracy target: 22/40 correct, 6 clean false alarms and
12 missed violations, versus A17's 25/40, 5 and 10 on the same replay. Keep
it disabled for deployed runs; see
[`attempts/A18-desk-object-history/README.md`](../attempts/A18-desk-object-history/README.md).
The replay script's `run --videos-dir /path/to/videos` remains an independent,
explicit opt-in for offline history comparisons.

### Frontend only, for UI development

```bash
cd frontend
npm install
npm run dev   # proxies /api to http://127.0.0.1:8000 (vite.config.ts)
```

### Tests

```bash
# backend
.venv/bin/python -m pytest tests          # unit/integration (skips GPU/ffmpeg-only tests when unavailable)
.venv/bin/ruff check backend

# frontend
cd frontend && npm test && npx tsc --noEmit && npm run build

# external acceptance suite against the deployed service
E2E_BASE_URL=https://forte-checker-wwi4jcrss.gobrev.dev \
E2E_API_KEY=<key> \
E2E_CLIPS_DIR=/path/to/clips \
.venv/bin/python -m pytest tests/e2e
```

`tests/e2e` uploads every `.mov` in `E2E_CLIPS_DIR`. It skips with an
explicit reason when the three `E2E_*` variables are not set, or when that
folder has no `.mov` files - it never silently passes or fails the whole suite
on a misconfiguration.

## 5. Key handover to the jury

The API key is generated by the team (not by the organizers, task.md §10)
and handed to the jury together with the service URL in the submission
package (task.md §8), out of band from this repository. It is never
committed, and it lives only in `.env` on the deployment host (mode 600).
To rotate it, change `API_KEY` in that `.env` and recreate the container
with the same `docker compose ... up -d` command (a plain restart keeps the old
environment).
