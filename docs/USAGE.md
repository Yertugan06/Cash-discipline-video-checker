# Usage

## 1. Submission details (jury)

| Item | Value |
| --- | --- |
| UI | TODO(team): public HTTPS URL, e.g. `https://<host>/` |
| API | same host, under `/api/v1` (see below) |
| API key | TODO(team): generated by the team and handed to the jury out of band (never committed; lives in `.env` on the host, mode 600) |

The API key is sent in the `X-API-Key` header. Requests without a valid key
get `401 Unauthorized`.

## 2. API

Two endpoints, matching task.md §10 exactly (the jury contract is never
renamed or extended with new required fields):

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/api/v1/analyze` | Upload a `.mov` video (`file` field). Returns `{"job_id": "..."}`. |
| `GET` | `/api/v1/jobs/{job_id}` | Poll status/result: `processing`, `done` or `failed`. |

Processing can take a few minutes; the jury contract allows up to 5 minutes
per video before it is counted as unprocessed (task.md §10, FAQ 14).

### Jury `curl` (verbatim form from task.md §10)

```bash
curl -X POST https://TODO-team-host.example/api/v1/analyze \
     -H "X-API-Key: <key>" -F "file=@video_017.mov"
# -> {"job_id": "3f2a9c1e"}

curl https://TODO-team-host.example/api/v1/jobs/3f2a9c1e \
     -H "X-API-Key: <key>"
```

A `done` response looks like this (see `backend/contracts.py:DoneJob` for the
exact, frozen required shape; the rule lifecycle, detection confidence, and
structured citation metadata are optional extras used by the UI, never
required by the jury contract):

  "status": "done",
  "verdict": "violation",
  "violations": [

      "timecode_sec": 44.2,

      "source_url": "https://adilet.zan.kz/rus/docs/V1900019680",
      "source_quote": "...",
      "strength": "direct",

### Health

- `GET /healthz` — liveness, no data in the body.
- `GET /readyz` — readiness (model serving reachable), no data in the body.

## 3. UI usage

1. Open the UI URL.
2. Enter the API key in the "API key" field. It is kept only in the page's
   memory for the current session — never written to `localStorage`,
   `sessionStorage`, a cookie, or the URL, and never shipped in the frontend
   bundle. Reloading the page clears it; it must be re-entered.
3. Choose a `.mov` video and submit.
4. The page shows an explicit "processing" state and polls the job until it
   is `done` or `failed`.
5. On `done`, the page shows the verdict, then, for every violation: its
   type, timecode (mm:ss and seconds), description, 1–3 evidence frames and
   the norm block (source act + punkt, verbatim quote, a link to the source,
   and a "verified"/"требует проверки" citation badge).
6. If the video could not be fully covered within the processing deadline
   (`coverage.mode != "full"`) or the pipeline reported quality warnings, a
   visible warning banner explains this before the results.
7. A "Пример (демо-данные)" / "Sample (demo data)" button in the upload panel
   loads a synthetic `DoneJob` fixture (`frontend/src/fixtures/sampleDoneJob.ts`)
   so the result layout can be reviewed without uploading a real video.

## 4. Running it yourself

### With Docker Compose (production-like)

```bash
cp .env.example .env   # TODO(team): add an .env.example once API_KEY/DETECTOR/VLM_* are finalised by WP1
# edit .env: set API_KEY; DETECTOR=f1 is the default and the deployed detector (DETECTOR=vlm + VLM_MODEL is the alternative)
# RULE_SCOPE=jury (default) reports only rules with human-verified citations and refuses to start
# while there are none; RULE_SCOPE=detector reports every enabled rule, citations marked pending.
docker compose -f compose.yaml [-f compose.gpu.yaml] up --build
# UI and API are served together on :8000 behind the reverse proxy (TLS terminated upstream)
```

See `backend/config.py` (`Settings`) for the full list of environment
variables and their defaults, and `archive/research1/architecture.md` §5 and §8 for
the resource budget and deployment/locality plan.

### Frontend only, for UI development

```bash
cd frontend
npm install
npm run dev   # proxies /api to http://127.0.0.1:8000 (vite.config.ts)
```

### Tests

```bash
# backend
.venv/bin/python -m pytest tests          # unit/integration (skips GPU/ffmpeg-only tests when unavailable)
.venv/bin/ruff check backend

# frontend
cd frontend && npm test && npx tsc --noEmit && npm run build

# external acceptance suite (needs a deployed, publicly reachable service)
E2E_BASE_URL=https://TODO-team-host.example \
E2E_API_KEY=<key> \
E2E_CLIPS_DIR=/path/to/clips \
.venv/bin/python -m pytest tests/e2e
```

`tests/e2e` skips with an explicit reason when the three `E2E_*` variables
are not set, or when `E2E_CLIPS_DIR` has no `.mov` files in it — it never
silently passes or fails the whole suite on a misconfiguration.
