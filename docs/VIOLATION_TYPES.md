# Violation types

task.md §8 asks for "перечень типов нарушений, которые распознаёт решение,
с кратким описанием каждого". The organizers do not publish a closed list
of violation types (task.md FAQ 8–9), so this is the list of mechanisms
**this service** checks for, each backed by a rule in the runtime Knowledge
Pack (`knowledge/rules.yaml` + `knowledge/norms.json`).

**The authoritative, per-rule list — title, trigger, anchor, and the exact
normative citation with its `citation_status` — is generated by WP3 at
[`docs/RULES.md`](RULES.md) from the Knowledge Pack.** This page is a
short, human-readable index grouped by mechanism, kept in sync with the
rule IDs actually present there.

Every `type` the API returns for a violation is one of these rules' Russian
title (`rules.yaml: title_ru`) — never a free-text label invented at
runtime (G4 checklist item 3, `archive/research1/implementation-plan.md`).

## Leaving the desk unattended (`L-*`)

The cashier steps away while something that should not be left unattended
is still out:

- **`L-NO-CASH-ON-LEAVE`** — cash/valuables left unattended: the cashier left the desk.
- **`L-SAFE-LOCKED-ON-LEAVE`** — the key is left in the safe lock.
- **`L-PC-LOCKED`** — the workstation (laptop) is left unlocked.
- **`L-NO-DOCS-ON-LEAVE`** — documents/media are left on the desk on leaving.

## Safe and cash handling (`S-*`)

- **`S-SAFE-CLOSED`** — the safe (storage) is left open.
- **`S-CLEAN-DESK-HANDOVER`** — the previous client's cash is not cleared before the next client is served.
- **`S-NO-MERGE`** — cash from different clients is mixed on the desk.

## Access / zone discipline (`A-*`)

- **`A-OUTSIDER-ZONE`** — an outsider is inside the cashier's booth.
- **`A-DOOR-LOCK`** — the cash-office door is not closed.
- **`A-SECOND-PERSON`** — more than one client is served at the same time.

## Client session (`C-*`)

- **`C-ID-BEFORE-CASH`** — cash is accepted without the client presenting a document.
- **`C-COUNT-BEFORE-EXIT`** — cash is not recounted in the client's presence before they leave.
- **`C-DETECTOR-CHECK`** *(disabled, experimental — see `docs/LIMITATIONS.md`)* — a recount without an authenticity-detector check.

## Workplace hygiene (`W-*`)

- **`W-NO-PERSONAL-ITEMS`** — personal items at the cashier's workplace.
- **`W-NO-FOOD`** — food/drinks at the cashier's workplace.
- **`W-NO-CAMERA-PHONE`** — a phone in the cashier's hands at the cash desk.

## Collector / escort (`K-*`)

- **`K-SEAL-CHECK`** — a collector's bag is accepted without inspection (the collector leaves immediately).
- **`K-RECOUNT-BEFORE-SAFE`** — cash from an opened bag goes into the safe without being recounted.

The rule set above mirrors `docs/RULES.md` as of this writing (18 rules: 17
enabled, 1 disabled/experimental). If WP3 adds, removes or renames a rule in
the Knowledge Pack, this list is a candidate for a follow-up edit — treat
`docs/RULES.md` as the source of truth whenever the two disagree.

## How a rule maps to a video (the three statements)

For every finding, the service keeps three statements distinct, never
merging them into one AI-written sentence (`archive/research1/architecture.md` §3):

1. **Observation** — the rule's description template filled with the
   actually measured facts and timecode, e.g. "с 41 по 49 с кассир вне
   рабочего места; на столе видны купюры".
2. **Claim** — "признаки возможного нарушения: `<rule title>`".
3. **Citation** — the act, punkt, verbatim quote and adilet.zan.kz link,
   shown with its `citation_status` badge (`docs/RULES.md` has the full
   table; `docs/LIMITATIONS.md` explains the badge).

## Mapping method

Rule → norm mapping is a deterministic lookup (`rule_id → norm_ids` in
`knowledge/rules.yaml`), not a retrieval or embedding search at runtime —
every citation a user can see was chosen ahead of time by a person
reviewing the public normative source, never generated on the fly by a
model (`archive/research1/architecture.md` §3, AGENTS.md "no invented results").
